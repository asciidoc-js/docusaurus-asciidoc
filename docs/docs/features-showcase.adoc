=== Syntax Highlighting Showcase

==== JavaScript with Callouts

[source,javascript]
----
const plugin = require('@asciidoc-js/docusaurus-asciidoc');

module.exports = {
  plugins: [plugin], // <1>
  presets: [
    ['classic', {
      docs: {
        include: ['**/*.{md,mdx,adoc}'], // <2>
      },
    }],
  ],
};
----
<1> Add the plugin to your config
<2> Include .adoc files in docs processing

==== Python Example

[source,python]
----
def setup_plugin():
    """Configure the AsciiDoc plugin for Docusaurus"""
    config = {
        'plugins': ['@asciidoc-js/docusaurus-asciidoc'],
        'presets': [{
            'classic': {
                'docs': {
                    'include': ['**/*.{md,mdx,adoc}']
                }
            }
        }]
    }
    return config
----

==== YAML Configuration

[source,yaml]
----
# docusaurus.config.js (partial)
plugins:
  - '@asciidoc-js/docusaurus-asciidoc'

presets:
  - classic:
      docs:
        include:
          - '**/*.{md,mdx,adoc}'
        sidebarPath: './sidebars.js'
----

== Performance Benefits

=== Direct AST Processing

Unlike other solutions that convert AsciiDoc → Markdown → HTML, this plugin:

. Parses AsciiDoc directly to AST
. Integrates with Docusaurus's MDX pipeline
. Avoids markdown serialization round-trips
. Maintains full Docusaurus feature compatibility

=== Benchmark Comparison

[cols="1,2,2", options="header"]
|===
| Approach | Steps | Performance

| Traditional
| AsciiDoc → Markdown → MDX → HTML
| Slower (multiple conversions)

| **This Plugin**
| AsciiDoc → AST → MDX → HTML
| **Faster** (direct AST integration)
|===

== Migration Path

=== From Markdown

. Install the plugin
. Configure `include: ['**/*.{md,mdx,adoc}']`
. Rename `.md` files to `.adoc` as needed
. Update syntax to AsciiDoc format

=== From Other Tools

. Export content to AsciiDoc format
. Set up Docusaurus with this plugin
. Configure routing and navigation
. Deploy and test
