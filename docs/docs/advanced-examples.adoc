== Inline Formatting Showcase

Plain text can contain *bold*, _italic_, `monospaced`, *_bold italic_*,
`*bold mono*`, _`italic mono`_, and *_`bold italic mono`_* combinations.

You can also use #highlighted (marked)# text, ^superscript^ notation,
~subscript~ notation, and even combine them: *bold with ^superscript^*
or _italic with ~subscript~ inside_.

Inline formatting can span
multiple words: *this entire phrase is bold* and _this entire
phrase is italic_ — they do not need to be single words.

Compile-time error::
An error detected by the compiler *before* the program runs.

----

+
These are often harder to diagnose because they depend on specific inputs
or environmental conditions.
+

Logic error::
The program runs without crashing but produces *incorrect results*.
+
These are the hardest bugs to find because no error message is generated.

== Admonitions — All Five Types

NOTE: This is a *note* admonition.  Notes provide additional context that
the reader might find useful but isn't critical to understanding the text.

TIP: This is a *tip* admonition.  Tips suggest best practices or shortcuts
that save time.

IMPORTANT: This is an *important* admonition.  Important blocks highlight
information that the reader _must not_ overlook.

WARNING: This is a *warning* admonition.  Warnings alert the reader to
potential pitfalls or dangerous actions.

CAUTION: This is a *caution* admonition.  Caution blocks indicate that
an action may cause irreversible consequences.

interface User {
  id: string;

function greetUser(user: User): string {

[source,python]

from dataclasses import dataclass, field
from typing import List

@dataclass
class Config:
    host: str = "localhost"
    port: int = 8080
    debug: bool = False
    allowed_origins: List[str] = field(default_factory=list)

    def base_url(self) -> str:
        scheme = "http" if self.debug else "https"
        return f"{scheme}://{self.host}:{self.port}"
----

[source,sql]
----
SELECT
    u.name,
    u.email,
    COUNT(o.id) AS order_count,
    SUM(o.total)  AS lifetime_value
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE u.created_at >= '2025-01-01'
GROUP BY u.id, u.name, u.email
HAVING COUNT(o.id) > 0
ORDER BY lifetime_value DESC
LIMIT 20;
----

== Paragraphs With Rich Inline Content

The `fromAsciidoc()` function accepts a *raw AsciiDoc string* and returns a
fully-typed `Document` node.  Under the hood it delegates to
https://github.com/asciidoctor/asciidoctor.js[@asciidoctor/core] for parsing,
then walks the Asciidoctor block model to produce an _adast_ tree that
conforms to the https://github.com/syntax-tree/unist[unist] specification.

Conversion to *mdast* is handled by `toMdast()`, which maps every adast
node type to its closest Markdown equivalent.  Types without a direct
counterpart — such as `admonition`, `sidebar`, and `descriptionList` — are
lowered into blockquotes, divs, or definition-list approximations, keeping
the content _lossless_ even if the structural semantics change.
